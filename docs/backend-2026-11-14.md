## Architecture and external services

The existing project host runs Next.js, FastAPI, one supervised Python worker,
PostgreSQL/pgvector and persistent scientific files. The worker uses bounded threads
for source refresh/transfers and fixed child processes for expensive registered
calculations. PostgreSQL holds leases, ordered events, temporary receipts, model
usage and release history. psycopg transactions and immutable, checksum-checked SQL
migrations provide database access without an ORM or separate migration service.

NASA PSI and NTRS provide public source data. Their actual observed interfaces,
source versions, rights and byte hashes are retained; their availability is not
assumed. OpenAI is the only configured paid API: GPT-6.1 Sol/Terra reasoning,
text-embedding-3-large retrieval and GPT-Live voice share the project connection.
No authentication, managed database, search cluster, execution vendor, notification
service or cloud resource was added. Hosting remains conditional and unprovisioned.

The project key was created through the approved secure flow and stored in the
ignored, mode-0600 `.env.local`. It is loaded only by the backend. Startup strips
provider/database secrets from the web process, and calculation children and
gVisor guests receive their own minimal environments. Public capability responses
report configuration without issuing paid health-check calls.

## Private selected inputs

Private selected files use the same browser receipt as temporary jobs, with
separate declared name, exact size/hash, intended use, user-asserted rights,
processing location and expiry. Ordered one-MiB chunks resume before explicit
final submission. The default host profile allows 64 MiB per file, 256 MiB/100
files per browser and one GiB/1,000 files on the host, with 24-hour expiry.
Byte budgets are configurable; JSON and archive validation retain separate
published bounds. Binary signatures are format checks, not a certification of
document contents or scientific measurements. Originals never enter the public
corpus automatically. See [private input contracts](evidence.md#selected-private-uploads).

Selected ready upload IDs are receipt/snapshot/hash-checked again before F13's
combined eight-MiB input copy. Exporting original private bytes requires explicit
permission even when a visitor labels the file CC0. Removing or expiring an
upload closes sessions that selected it; commands are denied immediately after
revocation, and guest teardown is observed before termination is recorded.
Downloaded exports and existing job artifacts have their own deletion/expiry.
Focused local checks exercise resumable exact bytes, denied cross-browser access,
hash/format/archive refusal, real NASA DOCX validation, quota/expiry cleanup,
actual gVisor computation of a known synthetic pressure difference and byte-exact
selected export. No paid API is used by those checks.

Selected temporary inputs can also accompany research and voice with separate
model-sharing consent. Their receipt, snapshot, expiry and exact hash are checked
again before bounded text/cell inspection. They keep `user_supplied_input` origin;
literal `user_input_summary` claims remain distinguishable from canonical NASA
measurements. The model's Python proposals can select those same authorized frozen
inputs, with an idempotency key covering code and input identities.

Follow-up requests carry only selected prior conversation turns: at most 16 turns,
6,000 characters per turn and 24,000 UTF-8 bytes of history. History does not
establish scientific evidence. Focused query/chart configurations are validated
and recomputed from their frozen source; highlighted passages use exact anchors.
Selected private artifacts require consent, ownership and snapshot/hash checks,
and preserve incomplete publication status. A local active-artifact identifier
without selected data has an explicit unavailable state. Full conversation/case
storage remains in the browser rather than being uploaded implicitly.

## Numerical and model behavior

Registered methods cover exact unit conversion, oxygen partial pressure,
condition/applicability comparison, ranking, trace fits, events/censoring,
detector timing/classification, dimensionless quantities, source-qualified
oxygen-consumption/heat-release calculations, uncertainty propagation, sensitivity
and information gain. Required physical definitions and inputs are typed; absent
or incompatible data produce an explicit refusal or a precise evidence gap.

Expensive fits use one numerical CPU thread, one concurrent child, 512 MiB address
space and 30-second CPU/elapsed limits, with bounded output and recorded resources.
Two different fits in one research request have distinct input-derived step keys.
User code follows the separate [gVisor execution boundary](execution.md).

Regression contracts require the complete shared physical-condition domain,
reference conditions and regime. Extra or missing condition keys are rejected.
One explicitly declared predictor condition may vary; other conditions stay fixed.
Source-backed non-applicability requires its exact anchor, quotation and rationale.
Anchor/quotation checks do not certify the semantic justification. Registration is
a local maintainer operation, with no public release endpoint or formal review role.

Scientific answers retain measured, calculated, predicted, interpreted,
hypothetical and unknown origins. Tool schemas, proposals and assumed scenarios
cannot establish NASA measurements. Numeric checks retain units and full stored
precision while permitting declared display rounding. Mechanical source/numeric
checks cannot independently certify causal interpretation. Raw inputs and derived
outputs remain separate throughout.
